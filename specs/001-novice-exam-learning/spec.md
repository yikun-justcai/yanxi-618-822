# Feature Specification: 618／822 从入门到真题的离线学习站

**Feature Branch**: `001-novice-exam-learning`（本目录未启用 Git 分支）  
**Created**: 2026-10-18  
**Status**: Draft  
**Input**: 面向大一公共管理新生，围绕长安大学 618 公共管理学和 822 公共政策学，利用本地 OCR 教材搭建能长期学习、回忆和真题训练的离线网站；Codex 与 DeepSeek Harness 共用 Spec Kit。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从零开始找到第一课 (Priority: P1)

没有专业基础的新生打开站点后，能看见 618／822 的学习路径，选择一个入门单元，读到简明解释、与其他概念的关系、可核对的教材出处，并进入对应题卡自测。学习过的单元在本机标记，下一次能继续。

**Why this priority**: 当前站点直接呈现题卡，缺少适合新生的起点与顺序。

**Independent Test**: 在空白浏览器数据中打开 `index.html`，不看使用说明，沿 618 或 822 完成一节课并进入相关题卡；刷新后单元状态仍在且旧题卡进度不变。

**Acceptance Scenarios**:

1. **Given** 初次访问，**When** 选择 618 入门，**Then** 看见按先修顺序排列的单元、明确的第一课和继续入口。
2. **Given** 打开一个单元，**When** 阅读解释与出处，**Then** 可区分已核对内容、OCR 待核对线索和非官方参考答案。
3. **Given** 完成学习自检，**When** 刷新页面，**Then** 该单元仍显示已学过，原题卡复习记录未丢失。

---

### User Story 2 - 从教材建立可审计的课程 (Priority: P2)

内容维护者能对五份现有 OCR Markdown 建来源清单，逐章识别、抽核并组织 618／822 的概念、机制和比较关系。学习站显示经审核的短篇改写内容及书名、版本、OCR 页码；缺失与疑似识别错误留下复核清单。

**Why this priority**: 内容可信度和覆盖范围决定站点能否长期用于考试准备。

**Independent Test**: 随机抽取每科三个单元，从站内出处回到本地 OCR 对应页段，并对照原 PDF 检查关键术语；未核对项不显示为已核对。

**Acceptance Scenarios**:

1. **Given** 有 OCR Markdown，**When** 内容维护者登记教材，**Then** 保留原文件、版次、页标记格式、识别问题及内容状态。
2. **Given** OCR 页码和原书页码不一致，**When** 展示出处，**Then** 明写“OCR 第 N 页”，不把它伪装成纸书页码。
3. **Given** 教材证据不足，**When** 编辑学习单元，**Then** 可以标为待复核，不能进入正式已核对课程。

---

### User Story 3 - 从回忆走到书面作答 (Priority: P3)

学生学完概念后能进行闭卷回忆、按名词解释／简答／论述／案例分析练习答题，看到题型结构和教材依据，对照答案后自行标出遗漏并进入复习队列。真题题干与参考答案清楚区分来源。

**Why this priority**: 高分要求把理解变成规范表达，而不只是“看懂答案”。

**Independent Test**: 从任一学习单元进入相关真题，独立输入作答、对照要点、记录薄弱点，再在“再练一遍”找到它；重练和筛选保持现有队列行为。

**Acceptance Scenarios**:

1. **Given** 尚未展开答案，**When** 学生练习，**Then** 答案不会提前显示或泄漏。
2. **Given** 已作答，**When** 展开参考答案，**Then** 可看见题型写法、要点和教材依据，并知道答案非官方。
3. **Given** 学生标记没想起，**When** 回到复习，**Then** 该题进入后续再练路径。

---

### User Story 4 - 保持多代理和离线维护 (Priority: P4)

维护者可以用 Codex 或 DeepSeek Harness 打开同一项目，读取同一份宪章、规格、计划和任务；两个代理都能发现教材转换 skill。重建题库后本地站仍能脱网使用。

**Why this priority**: 内容建设会持续多轮，协作时不能产生相互矛盾的规格或数据。

**Independent Test**: `specify integration status` 显示 codex 与 dsh 均完整，两个技能目录均可读；断网打开页面并完成题卡评分。

**Acceptance Scenarios**:

1. **Given** 两套代理入口，**When** 读取 Spec Kit 项目，**Then** 指向同一 `specs/001-novice-exam-learning/`。
2. **Given** 不提供 MinerU Token，**When** 学生打开网页，**Then** 阅读和题卡练习照常运行。

### Edge Cases

- OCR Markdown 有页标记但没有可靠章节标题：保留整书索引与待核对项，不自动猜测正式章节边界。
- 课与题卡关联的 ID 不存在：显示内容和明确的“暂无对应题卡”，不能跳到无关题目。
- 本地存储受限或清空：提醒进度不能保存，教材和预置题卡仍可阅读。
- 筛选后的真题已全部作答：显示本轮完成和重练入口，不把“已完成”混同“已掌握”。
- 窄屏、键盘和减少动画偏好：核心阅读与答题路径可完成，焦点可见。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 网站 MUST 明确标示仅面向长安大学 618／822，提供两科可跳学的先修学习路径。
- **FR-002**: 每个已发布单元 MUST 包含学习目标、新手可懂的解释、概念关系、自检问题、关联题卡、来源及审核状态。
- **FR-003**: 网站 MUST 在当前浏览器保存单元学习状态，并继续读取已有题卡与自建题卡数据。
- **FR-004**: 内容维护流程 MUST 记录五份 OCR 教材的原路径、书名版本、页标记、抽核结果和缺口。
- **FR-005**: 页面 MUST 区分 OCR 页码、纸书页码、真题原题、归纳改写及非官方参考答案。
- **FR-006**: 未审核教材内容 MUST 不得标为已核对或自动进入正式课程。
- **FR-007**: 学生 MUST 能从单元进入相关题卡，再回到学习路径；不存在关联题卡时须给出原因。
- **FR-008**: 闭卷作答与答案揭示 MUST 分离，至少保留现有的错题记录、到期复习和真题本轮队列行为。
- **FR-009**: 所有学生端功能 MUST 在无网络、无账号、无 API Token 时运行。
- **FR-010**: Codex 和 DSH MUST 读取同一套 Spec Kit 规格，且项目内可发现 `mineru-textbook-to-md` skill。

### Key Entities *(include if feature involves data)*

- **Source**: 教材或真题文件；书名、版本、原路径、OCR 页码体系、审核状态。
- **Unit**: 一个可学习考点；科目、顺序、目标、解释、概念关系、先修、题卡 ID、来源定位和状态。
- **Card**: 现有题库问题、答案、年份、题型、考点、出处及复习 ID。
- **LearnerProgress**: 单元完成情况和现有题卡的回忆评分记录，只存当前浏览器。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首次访问者在 2 分钟内能从首页进入 618 或 822 的第一课，并找到该课的自检题卡。
- **SC-002**: 首版两科各至少有一个从入门解释到题卡自测的完整学习链；扩展前须有逐章覆盖清单，不把首版称为全考纲覆盖。
- **SC-003**: 每个已发布单元的关键陈述都能回到标明书名和 OCR 页码的本地材料；抽样复核无无法定位的声称“已核对”内容。
- **SC-004**: 390px 与桌面宽度下，键盘可完成选课、读课、进入题卡、查看答案、评分；页面无水平溢出。
- **SC-005**: 重建页面后，原有 275 张题卡数量及既有本地进度键保持可用；新内容不依赖网络请求。
- **SC-006**: `specify integration status` 无缺失或修改的托管文件，Codex 与 DSH 均已安装。

## Assumptions

- 学生使用同一台设备和浏览器；首版无跨设备同步。
- 站点只在本地离线使用，不公开传播完整教材 OCR 内容。
- `D:\考研备考\OCR全文` 的五份 Markdown 是本机现有输入；需逐段抽核，不能因为文件存在就视作准确。
- 现有题卡和真题作为可用起点，其准确性仍需分批复核。
- “高分”是学习目标，实际成绩受个人学习、考试变化和资料准确性影响；产品不作成绩保证。

## Amendment 1（2026-10-18）：范围收窄与交付形态变更

**原因**：用户反馈首版「只是在背诵」，题卡问答不构成学习；并要求先做一个科目。原规格把两科、275 张题卡当起点，与新的学习闭环不匹配。

**影响文件**：`index.html`、`build_site.py`、`course/`、`tools/selftest.py`、`使用说明.md`、本文件、`tasks.md`。

**迁移方式**：822 内容不从源文件删除（`exam_content.py`、`reference_answers.py` 保留），只是不编入页面；旧的 `yanxi-study-v1` 题卡进度不迁移，新的学习进度写入 `yanxi-618-v2`。

新增/变更的需求：

- **FR-011**: 首版 MUST 只交付 618 公共管理学；822 内容保留在源文件，不进入学生端页面。
- **FR-012**: 学习的最小单元 MUST 是「课时」，每课时 MUST 含可检验的学习目标、讲解、至少 4 道即时练习、一次限时书写任务与其得分点清单。
- **FR-013**: 每个课时 MUST 标注审核状态：`quote-checked`（教材引文已由构建脚本逐条回查，讲解为归纳改写）或 `reviewed`（已人工逐句抽核）。未达 `reviewed` 的课时 MUST 在页面上如实标明，不得显示为已核对。
- **FR-014**: 构建 MUST 校验每条教材依据能在其标注的 OCR 页码（或真题 PDF）中回查到原文；任一条失败 MUST 中止且不覆盖 `index.html`。
- **FR-015**: 仓库 MUST 提供可重复运行的浏览器端回归（`tools/selftest.py`），界面或内容改动后 MUST 运行并全部通过。
- **FR-016**: 课时的完成状态 MUST 由行为决定（练习全部作答 + 写作对照过要点），不得只由自评决定。
